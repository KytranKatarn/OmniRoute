# PR #3986 review-path corrections — 2026-10-20

The existing host job reviewed only the first 60,000 bytes of #3986's 210,084-byte
diff, then posted a REQUEST_CHANGES review. Queue status lost the running request
when the host moved its JSON out of pending/. These were observed from the host log
and GitHub review; this investigation did not launch that job.

Review: https://github.com/KytranKatarn/archie-platform/pull/3986#pullrequestreview-5586117183

## Changes

- Track running requests and their current logs; block duplicate enqueue and avoid
  showing an earlier run's log while a new request is pending.
- Retrieve GitHub's full raw diff, send the prompt through stdin, and refuse an
  explicit size limit rather than silently reviewing a prefix. Failed model runs
  cannot be reported as completed.
- Use a real local repository directory for Git operations (previously owner/name
  was incorrectly passed to git -C). Fail on fetch/checkout errors, verify the
  checked-out SHA, and use disk-backed worktrees instead of small /tmp tmpfs.
- Refuse a head change during diff retrieval. Pin posted reviews to the reviewed
  commit, preserve COMMENT transport by default, and return failure if posting fails.
- Import Codex verdicts in the common poll service for scheduled and manual polls,
  filtering tracked PRs by repository. Import failure preserves successful PR sync.
- Show current Codex REQUEST_CHANGES even when Forge is pending/in progress; closed
  PRs remain closed and stale refusals retain the ordinary waiting/reviewing state.
- Correct the advisory-only tooltip. Watch a queued request's identity, sync GitHub
  after completion, clear cached lists, and refresh both PR surfaces automatically.
