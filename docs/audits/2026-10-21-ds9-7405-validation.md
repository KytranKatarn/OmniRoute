DS9 local branch `fix/ds9-7405-client-tools`, commit
`a4c8f5638` in `/mnt/standalone/deep-space-9/.claude/worktrees/ds9-7405-client-tools`.
The three-file change is preserved in `codex/patches/ds9-7405-client-tools.patch.gz`.
The gzip wrapper preserves patch whitespace through repository formatting hooks.
Decompress before `git apply --check` and application.
This repository PR transports that patch; merging it does not apply or build DS9.
The DS9 fork's public upstream is not the destination for this local integration.

The actual CLI advertises tools inside developer `additional_tools` input items,
including namespaced custom tools. The old adapter advertised zero of the CLI's
11 tools. Reading only top-level declarations also discarded custom `functions.exec`.
The patch accepts structured declarations, preserves namespace and custom-tool
identity in JSON and SSE, and preserves message roles when replaying results as
text. Top-level declarations take precedence; user-role declarations are ignored.
The upstream's own shell and multi-agent tools are disabled for these client-tool
threads. Its read-only sandbox, never-approve policy and auto-approval setting
remain restrictive.

The terminal launcher change loads the existing KB bearer for independent
`docker exec` invocations; entrypoint exports do not reach those invocations.
An unreadable mounted bearer produces an explicit failure. No secret bytes or
ownership changes are part of this PR.

## Outstanding gates

1. The running terminal's Docker default confinement still prevents the CLI's
   namespace sandbox from starting. The legacy Landlock backend was tested and
   rejected: workspace-write panics because direct-runtime permission profiles
   are incompatible. Do not enable it for coding or disable confinement broadly.
   A tested, narrowly scoped candidate policy is now included in `codex/security/`;
   security review and a controlled live-terminal activation rehearsal remain.
2. The current DS9 key mount is root-owned mode 0600. The candidate terminal runs
   as UID 1000, so its dedicated DS9 key must become UID/GID 1000 mode 0400 during
   a coordinated activation. Verify identical bytes by digest; do not print or
   rotate the key as part of this change. The KB mount already supports UID 1000.
3. The real CLI initialized the disposable MCP server and listed its tool, but
   the code-mode model runtime reported that the tool was absent from `ALL_TOOLS`;
   no MCP call occurred. Keep design MCP disabled until a model-driven tool call
   and result are demonstrated. Direct HTTP acceptance is insufficient.
4. Review and apply the DS9 patch to a clean local integration branch, run its
   remaining required suites, build an isolated candidate, and verify deployment
   provenance before activating. Preserve the live fork's unrelated edits.
5. Repeat file-edit and read-only controls in the actual terminal after its
   confinement issue is resolved; separately verify resume and model-driven MCP.

No live gateway source, running image, owner login, upstream approval policy or
production service was changed by this package. The named host AppArmor profile
used for the disposable test was unloaded afterward.
