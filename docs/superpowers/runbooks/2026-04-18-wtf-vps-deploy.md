## Phase C4 — Caddy stanzas for WTF domains

Still on the VPS:

```bash
cat >> /etc/caddy/Caddyfile <<'EOF'

what-the-fact.com {
    reverse_proxy localhost:8103
    encode zstd gzip
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options "nosniff"
        Referrer-Policy "strict-origin-when-cross-origin"
    }
    log {
        output file /var/log/caddy/wtf-consumer.log
    }
}

what-the-fact.tech {
    reverse_proxy localhost:8104
    encode zstd gzip
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options "nosniff"
        Referrer-Policy "strict-origin-when-cross-origin"
    }
    log {
        output file /var/log/caddy/wtf-tech.log
    }
}
EOF

caddy validate --config /etc/caddy/Caddyfile
# expected: "Valid configuration"

systemctl reload caddy && systemctl status caddy --no-pager | head -5
# expected: active (running)
```

**Note:** Caddy will try to issue Let's Encrypt certs the first time each domain is hit. That only works if DNS already points to this VPS — and DNS cutover (C5) is still pending. So you may see cert-issuance errors in the Caddy log until I run C5. That's expected. Don't panic.

## Rollback

If anything goes wrong during C3/C4:

```bash
# Rollback compose
cp /root/archie-outpost/docker-compose.yml.bak_$(date +%Y%m%d) /root/archie-outpost/docker-compose.yml
docker compose down wtf-ingest wtf-consumer wtf-tech 2>/dev/null

# Rollback Caddy
cp /etc/caddy/Caddyfile.bak_$(date +%Y%m%d) /etc/caddy/Caddyfile
systemctl reload caddy

# Restore kytran_news
docker run --name kytran_news -d ... kytran_news_archive:YYYYMMDD   # you'll need the original run args — the backed-up compose block has them
```
