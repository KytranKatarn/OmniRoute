# KSM Stripe Billing — Wire Feature Gating to Stripe Subscriptions

**Date**: 2026-03-26
**Project**: #195 — Unified Stripe Billing — Platform-Wide Payment Integration
**Status**: Design Approved
**Scope**: Sub-Project 2 — Register KSM products in Stripe, checkout flow from standalone, webhook handler pushes tier updates to standalone
**Depends on**: Stripe Core (done), KSM Feature Gating (done)

---

## Problem Statement

KSM has feature gating by tier (free/pro/business/enterprise) with admin override for internal use. External users need to pay via Stripe to upgrade. When Stripe confirms payment, the standalone's tier must update immediately.

---

## Flow

```
User clicks "Upgrade to Pro" on standalone
  → Standalone calls ARCHIE hub: POST /api/billing/checkout {price_id, success_url, cancel_url}
  → Hub creates Stripe Checkout Session, returns URL
  → User redirected to Stripe Checkout page
  → User pays
  → Stripe redirects to success_url on standalone
  → Stripe fires checkout.session.completed webhook to ARCHIE
  → ARCHIE webhook handler maps price → tier
  → ARCHIE pushes tier update to standalone: POST {standalone}/api/billing/tier-update {user_id, tier}
  → Standalone calls set_user_tier() → features unlocked immediately
```

## Deliverable 1: Register KSM Products in Stripe

One-time setup — create products + prices via Stripe API, store in `billing_products`.

| Product | Price | Stripe Price ID | Tier |
|---------|-------|----------------|------|
| KSM Pro | $29/month | (generated by Stripe) | pro |
| KSM Business | $49/month | (generated by Stripe) | business |
| KSM Enterprise | $99/month | (generated by Stripe) | enterprise |

Script creates products via `stripe.Product.create()` + `stripe.Price.create()`, then registers in `billing_products` table via `stripe_service.register_product()`.

## Deliverable 4: Standalone Tier Update Receiver

**New endpoint on standalone**: `POST /api/billing/tier-update`

- Authenticated via hub client credentials (same as compliance reporting)
- Accepts: `{"user_id": int, "tier": "pro"|"business"|"enterprise"|"free"}`
- Calls `set_user_tier(user_id, tier)` from subscription_service
- Returns `{"success": true}`

## Success Criteria

1. 3 KSM products registered in Stripe + billing_products table
2. Clicking "Upgrade to Pro" on standalone redirects to Stripe Checkout

4. Standalone features unlock immediately after tier update
5. Subscription cancellation in Stripe → tier reverts to free
6. Tier change (upgrade/downgrade) → pushed and applied
7. Internal instance (TIER_OVERRIDE=enterprise) unaffected by Stripe events
