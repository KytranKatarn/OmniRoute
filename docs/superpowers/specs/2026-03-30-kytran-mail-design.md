**Status:** Design approved

## Overview

Kytran Mail is a branded, fleet-deployable mail server product. Stalwart Mail Server under the hood, LCARS admin dashboard on top, deployable via KSO App Catalog on any fleet node.

**Phase A (this spec):** Branded container + LCARS dashboard with mailbox CRUD + health monitoring.

**Future phases (not in scope):**
- Phase B: Distributed mail routing across fleet nodes (EU outpost handles EU mail, US handles US)
- Phase C: Custom webmail UI for end users, self-service mailbox creation, subscription billing

## Architecture

```
┌─────────────────────────────────────┐
│  Kytran Mail Container              │
│  ┌──────────┐  ┌─────────────────┐  │
│  │ LCARS    │  │ Stalwart Mail   │  │
│  │ Dashboard │  │ Server v0.11.8  │  │
│  │ (Flask)  │──│ (SMTP/IMAP/API) │  │
│  │ :8025    │  │ :25/587/993     │  │
│  └──────────┘  │ :8443 (admin)   │  │
│                └─────────────────┘  │
└─────────────────────────────────────┘
```

Single Docker container running both Stalwart and a thin Flask dashboard. The Flask app talks to Stalwart's management API internally (localhost:8443). Supervisor or a simple entrypoint script manages both processes.

## Domain & Branding

- Domain is configurable per deployment via `MAIL_DOMAIN` env var
- Default for hub: `kytranempowerment.com`
- Fleet nodes set their own domain when deploying via KSO App Catalog
- Domain DNS/DKIM management stays in Security Network module — Kytran Mail only displays domain config status (read-only)

## LCARS Dashboard (port 8025)

### Dashboard Tab
- Server health indicator (up/down, uptime)
- Total mailbox count
- Storage used / quota
- Mail queue status (pending, deferred, failed counts)
- Last 10 messages summary (from, to, subject, timestamp, direction)

### Mailboxes Tab
- Table listing all mailboxes: email, display name, status (active/disabled), storage used, last login
- **Create mailbox:** name, display name, password, quota (MB)
- **Delete mailbox:** with LCARS red alert confirmation modal
- **Reset password:** new password input + confirmation
- **Enable/disable account:** toggle switch
- Search/filter by name

### Settings Tab
- Configured domain (read-only — managed in Security Network module)
- DKIM status indicator (configured or not, shows selector + public key fingerprint)
- TLS certificate status
- Relay configuration display (upstream relay host if configured)
- Link to Stalwart full admin UI (:8443) for advanced configuration
- Server version display

## API Endpoints (Flask Dashboard)

```
GET  /                          — redirect to /dashboard
GET  /dashboard                 — main dashboard page
GET  /api/health                — health check for catalog/monitoring
GET  /api/status                — server status (uptime, version, queue)
GET  /api/mailboxes             — list all mailboxes
POST /api/mailboxes             — create mailbox {email, display_name, password, quota_mb}
DELETE /api/mailboxes/<email>   — delete mailbox
POST /api/mailboxes/<email>/password  — reset password {password}
POST /api/mailboxes/<email>/toggle    — enable/disable {enabled: bool}
GET  /api/queue                 — mail queue summary
GET  /api/messages/recent       — last 10 messages
```

All API endpoints proxy to Stalwart's management API (localhost:8443) with the admin credentials.

## Stalwart Management API Integration

Stalwart exposes a REST API on port 8443. Key endpoints used:

- `GET /api/store/accounts` — list accounts
- `POST /api/store/accounts` — create account
- `DELETE /api/store/accounts/<name>` — delete account
- `PATCH /api/store/accounts/<name>` — update account (password, enabled, quota)
- `GET /api/queue/list` — mail queue
- `GET /api/telemetry/metrics` — server metrics

Authentication: Bearer token using the admin password.

## LCARS Dashboard UI

### Theme
- Dark background (#0a0e17), panel (#111827)
- Accent: teal (#00e5ff) for mail/active, amber for warnings, red for errors
- Fonts: Orbitron (titles), IBM Plex Mono (body)
- LCARS frame with sidebar segments, elbow corners
- Consistent with KSO and other Kytran products

### Dashboard Tab Layout
- Hero stats bar: Mailboxes | Storage Used | Queue | Uptime
- Recent messages list (from, to, subject, time, direction arrow)
- Server health card with status indicator

### Mailboxes Tab Layout
- Search bar + "Create Mailbox" button
- Table: Email | Display Name | Status | Storage | Last Login | Actions
- Actions column: Reset Password, Toggle, Delete
- Create mailbox: LCARS modal with form fields

### Modals
- Create Mailbox: LCARS modal (teal accent)
- Reset Password: LCARS modal (amber accent)
- Delete Mailbox: LCARS red alert modal with confirmation
- Stalwart Admin Link: opens Stalwart's :8443 in new tab

## Error Handling

- Stalwart API unreachable: dashboard shows "Server Offline" banner, retries every 30s
- Invalid mailbox create (duplicate, invalid chars): show error toast from Stalwart's response
- Delete with active queue: warn that pending messages will be lost
- Health endpoint returns 503 if Stalwart process is down

## Migration from Current Stalwart

The hub currently runs Stalwart standalone in `stalwart-mail/` directory. Migration path:
1. Build Kytran Mail container image
2. Add catalog entry to `fleet/catalog/apps/kytran-mail.yml`
3. Deploy via KSO App Catalog (or manually on hub)
4. Mount existing DKIM keys and data volume
5. Existing accounts and mail preserved (same Stalwart data format)

The `stalwart-mail/` directory config becomes the template for `config.toml.template`.

## What's NOT in Phase A

- Domain/DNS management (owned by Security Network module)
- Custom webmail UI for end users (phase C)
- Multi-node mail routing / regional delivery (phase B)
- Subscription billing / feature gating (phase C)
- Spam filtering UI (use Stalwart admin)
- Mailing lists / distribution groups (phase C)
- Calendar/contacts (CalDAV/CardDAV — phase C)
