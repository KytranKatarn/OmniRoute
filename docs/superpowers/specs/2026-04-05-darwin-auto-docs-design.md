# Auto-Generate Missing Docs via D.A.R.W.I.N. — Design Spec

**Date:** 2026-04-05
**Project:** #221 — Agent-Driven Knowledge Intelligence Phase 2
**Task:** #1635 — Auto-generate missing docs via D.A.R.W.I.N. agent
**Status:** Approved design, pending implementation

---

## Problem

Projects with knowledge gaps (below 50% completeness) have no documentation until a human writes it. The gap analysis identifies what's missing but nothing acts on it. Meanwhile, D.A.R.W.I.N. (R&D director) sits idle with the capability to analyze project state and generate useful reports.

## Goals

1. **Auto-generate project intelligence reports** for projects with low completeness scores.
2. **Distinguish auto-generated drafts from human docs** so they don't game the completeness score.
3. **Provide manual trigger** via dashboard button alongside the scheduled job.
4. **Follow existing patterns** — Job #48 dispatch pattern, consciousness job registration, vault_note storage.

---

## Job Design

### Registration

- **Job name:** `auto_generate_project_docs`
- **Location:** `tools/consciousness/jobs.py` (alongside other consciousness jobs)
- **Schedule:** Every 6 hours via `IntervalTrigger(hours=6)`
- **Logging:** `_log_cycle("auto_generate_docs", ...)` to `autonomy_loop_log`

### Flow

1. Call `get_all_gaps(status="active,planning")` from `knowledge_link_service`
2. Filter: `completeness < 50` AND no vault_note with `source_type='auto_documentation'` tagged with project slug in last 7 days
3. Sort by completeness ascending (worst first), take max 3
4. For each project:
   a. Fetch project details: name, description, tasks (from `unified_tasks`), recent decisions (from `project_decisions`)
   b. Build prompt with project context + gap analysis
   c. Dispatch: `get_dispatcher().request_work(capability="auto_document", json_mode=True, project_id=project_id, prefer_agent="D.A.R.W.I.N.", module_id="consciousness")`
   d. Parse JSON response: `{title, summary, recommendations, key_findings}`
   e. Store as vault_note in `knowledge_base`
   f. Link to project via `link_knowledge_to_project(kb_id, project_id, link_type='auto', confidence=0.90)`
5. Log cycle with items_processed / items_failed counts

### Cooldown Check

Query `knowledge_base` for entries matching:
```sql
WHERE source_type = 'auto_documentation'
AND tags @> ARRAY['project-slug-here']
AND created_at > NOW() - INTERVAL '7 days'
```
If any exist for a project, skip it.

## Prompt Design

Sent to D.A.R.W.I.N. via Bridge dispatch:

```
You are generating a project intelligence report for "{project_name}".

Project description: {description}
Current completeness: {completeness}%
Missing: {gap_list}

Tasks ({task_count} total, {completed} completed):
{task_summaries}

Recent decisions:
{decision_summaries}

Generate a JSON response with:
- title: A descriptive title for this project report
- summary: 2-3 paragraph overview of the project state, what's been accomplished, what remains
- recommendations: List of 3-5 specific actions to improve this project's knowledge coverage
- key_findings: List of 2-3 insights about the project's trajectory or risks
```

## Gap Analysis Adjustment

### Anti-Feedback-Loop Rule

The `vault_note` gap in `get_project_knowledge_gaps()` must only count non-auto-generated entries:

```sql
-- Current: counts ALL vault_notes
count(*) FILTER (WHERE knowledge_type = 'vault_note')

-- New: counts only human/verified vault_notes
count(*) FILTER (WHERE knowledge_type = 'vault_note'
                 AND (source_type IS NULL OR source_type != 'auto_documentation'))
```

This prevents the system from generating docs to fill its own gaps. Auto-generated docs are visible and useful but don't satisfy the completeness score.

### New Gap Sub-Status

When a project has auto-generated docs but no human docs:
- Gap chip changes from "DOCS" (red/missing) to "DRAFTS ONLY" (orange)
- Indicates documentation exists but needs human review

## Dashboard Integration

### New API Endpoint

`POST /tools/consciousness/api/dashboard/generate-docs`
- Body: `{project_id: int}`
- Triggers doc generation for one specific project (bypasses 50% threshold and cooldown)
- Returns: `{success: true, message: "Report generation queued"}`
- Requires `@admin_required`

### Knowledge Gaps Panel Changes

- New "Generate Report" button next to "+ Decision" and "+ Docs" for each project
- Button disabled + shows "Report pending" if auto-doc exists from last 7 days
- Shows spinner while dispatching, then confirmation message

### Project-Knowledge Map Changes

- Linked entries with `source_type='auto_documentation'` show "DRAFT" badge (orange) instead of "AUTO" (teal)
- Distinguishes AI-generated drafts from auto-linked existing knowledge
