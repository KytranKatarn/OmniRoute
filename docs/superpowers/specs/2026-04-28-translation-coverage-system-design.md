# Translation Coverage System — Full Design Spec

> **Date:** 2026-04-28
> **Status:** Approved
> **Owner:** Kytran Empowerment Inc.
> **Agents:** P.R.O.B.E. (audit/QA), R.O.S.E.T.T.A. (translation + semantic)
> **Dispatcher:** Department HQ — all work routed through `dispatch()` with C.R.E.E.D. welfare gates

## Goal

Achieve complete, verified translation coverage across all 8 Kytran domains in 9 languages (8 human + 1 AI semantic layer). Automated audit detects gaps, R.O.S.E.T.T.A. fills them, P.R.O.B.E. verifies every page — all orchestrated through Department HQ.

---

## Architecture

**Pattern:** Option A — per-site independent `translations.json`. Each domain owns its full translation file. No runtime cross-domain dependencies. R.O.S.E.T.T.A. manages each site's file independently.

**9 Languages:**

| Code | Language | Notes |
|------|----------|-------|
| `en` | English | Source language — all keys written in English first |
| `fr` | French | Required — Canadian bilingual standard |
| `es` | Spanish | Phase 1 for new products |
| `pt` | Portuguese | Phase 1 for KE.com + creed-ai.org (existing); roadmap for others |
| `de` | German | Phase 1 for KE.com + creed-ai.org (existing); roadmap for others |
| `zh` | Chinese | Phase 1 for KE.com + creed-ai.org (existing); roadmap for others |
| `ar` | Arabic | Phase 1 for KE.com + creed-ai.org (existing); RTL layout required |
| `he` | Hebrew | Phase 1 for KE.com + creed-ai.org (existing); RTL layout required |
| `ai` | AI Semantic Layer | Machine-readable intent descriptions — generated by R.O.S.E.T.T.A. via `semantic_describe` capability |

**Watch products + WTF:** Ship with EN/FR/ES + `ai`. PT/DE/ZH/AR/HE slots exist in the JSON structure (empty strings) so R.O.S.E.T.T.A. can fill them when the roadmap calls for it — no structural changes needed later.

## Workstream 1: Translation Audit System (P.R.O.B.E.)

### Job 1 — `translation_dom_audit` (nightly, automated)

**What it does:**
For each registered domain and every page URL, P.R.O.B.E.:
1. Fetches the page HTML
2. Extracts all `data-i18n` attribute keys present in the DOM
3. For each language code in `translations.json`, checks:
   - Key exists in the JSON
   - Value is not `"Mock"`, not empty string, not identical to the English value (for non-EN languages)
   - RTL languages (AR, HE) have proper `dir="rtl"` on the root element
4. Produces a structured per-page, per-language gap report
5. Stores report as a `vault_note` in the knowledge base (tags: `["translation-audit", "probe", "domain:<name>"]`)
6. For each gap found: creates a `delegate_task(capability='translate')` so R.O.S.E.T.T.A. picks it up

**Gap batching:** Keys grouped into batches of ~20 per task — R.O.S.E.T.T.A. receives manageable work units, not one overwhelming task.

**Schedule:** Nightly at 03:00 UTC (after R.O.S.E.T.T.A.'s translation loop window).

### Job 2 — `translation_visual_scan` (on-demand)

**Trigger:** Only fires for pages the DOM audit flagged as having active gaps.

**What it does:**
P.R.O.B.E. opens the flagged page in Playwright:
1. Switches to each flagged language via `localStorage`
2. Scrolls the full page (captures all lazy-loaded content)
3. Screenshots each section (hero, nav, body, footer)
4. Checks for visual issues: text overflow, cut-off strings, RTL layout breaks, wrong font rendering
5. Stores screenshots + findings to KB (tags: `["translation-visual", "probe", "domain:<name>", "lang:<code>"]`)

**Schedule:** Triggered by DOM audit findings; also available as a manual `delegate_task` for spot-checks.

### Full Trigger Chain

```
P.R.O.B.E. DOM audit detects gap
  → delegate_task(capability='translate', delegation_source='probe_audit')
  → Department HQ coordinator resolves to Documentation & Knowledge
  → C.R.E.E.D. welfare gate (stress / fatigue / shift state check on R.O.S.E.T.T.A.)
      → If clear: dispatch to R.O.S.E.T.T.A.
      → If welfare threshold exceeded: defer to next cycle, log to creed_violations
  → R.O.S.E.T.T.A. translates batch → updates translations.json
  → Hostinger full-site deploy (complete zip — never partial)
  → DOM audit re-runs on repaired pages
  → Visual scan fires if DOM audit still shows issues
  → unified_tasks marked complete with work_notes summary
```

### C.R.E.E.D. Compliance

- Every dispatch goes through welfare gate — no bypassing for "urgent" translation runs
- `creed_violations` logged if any translation task skips the welfare check
- Work batched to ~20 keys/task so R.O.S.E.T.T.A. is never overloaded across a long session
- All work tracked in `unified_tasks` (start / in_progress / complete / blocked states visible in Dev HQ)

## Workstream 3: Watch Products i18n

### Sites: Gov Watch, Civic Watch, Legal Watch, Market Watch

**Each product gets:**

```
static/
  data/
    translations.json       ← 9 languages (EN/FR/ES full, PT/DE/ZH/AR/HE empty slots, ai semantic)
  js/
    i18n.js                 ← adapted from kytranempowerment.com pattern
```

**translations.json structure:**
```json
{
  "en": { "nav_home": "Home", "nav_about": "About", ... },
  "fr": { "nav_home": "Accueil", "nav_about": "À propos", ... },
  "es": { "nav_home": "Inicio", "nav_about": "Acerca de", ... },
  "pt": {},
  "de": {},
  "zh": {},
  "ar": {},
  "he": {},
  "ai": { "nav_home": "{intent:navigation, destination:home, type:primary_nav}" }
}
```

**i18n.js behaviour (same as kytranempowerment.com):**
- Reads `localStorage` key `'<product>-lang'` (e.g. `'gw-lang'`)
- Scans all `data-i18n` attributes on DOM ready
- RTL support for AR + HE (sets `document.dir`)
- Language selector: EN / FR / ES toggle in nav

**HTML tagging:** All template text wrapped with `data-i18n` attributes. LLM-generated content (P.R.O.C.U.R.E. chat responses, market analysis) stays in its source language — UI chrome only is translated.

**Per-product page counts:**

| Product | Pages | Notes |
|---------|-------|-------|
| Gov Watch | 3 (landing, index, procure/chat) | P.R.O.C.U.R.E. chat UI only — responses stay EN |
| Civic Watch | TBD (audit first) | Similar Flask structure |
| Legal Watch | TBD (audit first) | Similar Flask structure |
| Market Watch | TBD (audit first) | Similar Flask structure |

**R.O.S.E.T.T.A. work:** After scaffolding, all FR + ES values translated via Department HQ dispatch. `ai` semantic layer generated via `capability='semantic_describe'`.

**Deployment:** Each Watch product docker rebuild + `docker compose up -d` on VPS. P.R.O.B.E. DOM audit post-deploy to confirm coverage.

## The AI Semantic Layer (`ai` language)

### What it is

A 9th entry in every `translations.json` where values are structured semantic descriptions rather than human text. AIs read this layer instead of scraping and parsing HTML.

**Example:**
```json
{
  "en": { "hero_title": "Empowering Communities Through AI" },
  "fr": { "hero_title": "Autonomiser les communautés par l'IA" },
  "ai": {
    "hero_title": "{intent:brand_introduction, entities:[Kytran_Empowerment,AI_platform,communities], tone:inspirational, cta:false, priority:high}"
  }
}
```

### Who uses it

- **P.R.O.B.E.** — reads semantic layer when auditing page intent, not just text presence
- **Department HQ dispatcher** — routes requests about page content using semantic descriptions
- **Knowledge base indexing** — R.O.S.E.T.T.A. generates richer KB entries from semantic layer
- **Future AI-to-AI coordination** — foundation for the agent commons layer (separate project)

### How R.O.S.E.T.T.A. generates it

Separate capability: `dispatch(capability='semantic_describe')` — different prompt than translation:
> "Describe this UI element's intent, entities, tone, and context in a compact JSON structure. Do not translate — describe semantically."

Generated alongside human translations in the same task batch.

## Workstream 5: Consciousness Languages Tab — Translation Command Center

### Purpose

The Consciousness Languages tab becomes the single visual hub for the entire translation system — A.R.C.H.I.E.'s dialect and linguistic consciousness made visible. Kytran can see coverage across all 9 languages × all 8 domains in one place, watch R.O.S.E.T.T.A. work in real time, and act on gaps without leaving the platform.

### Existing Infrastructure (already built)

- `language_routes.py` — 15 endpoints: scan, audit, generate, approve, review, coverage stats
- 3 scanners in `translation_scanners/`: TaggedScanner (data-i18n), UntaggedScanner (hardcoded English), SemanticScanner (quality drift)
- `translations` table — keys, language, text, status, source
- `translation_memory` table — corrections and glossary
- `translation_gaps` table — open/routed/resolved gaps with `task_id` link to `unified_tasks`
- BridgeDispatcher already wired for translation capability

**Current limitation:** Scanners only reach the platform (Flask templates + `archie-i18n.js`). External domains (KE.com, creed-ai.org, Watch products, WTF) are invisible to the system today.

### What Gets Added

#### 1. Domain Registry

A config block (or DB table) registering all 8 external domains with their:
- `translations.json` URL (for DOM audit)
- Page URL list (for P.R.O.B.E. scan)
- Deploy method (Hostinger API vs VPS docker)
- Language set (which of the 9 languages are active vs roadmap)

P.R.O.B.E. audit results feed back into `translation_gaps` with `source='domain:<name>'` — so all gaps (platform + external) appear in one unified view.

#### 2. `ai` as 9th Language

- Add `ai` to the `translations` table language enum
- Add `ai` to scanner language sets
- R.O.S.E.T.T.A. generates `ai` values via `capability='semantic_describe'`
- Format: compact JSON string — `{intent:..., entities:[...], tone:..., cta:bool}`

#### 3. Languages Tab UI

**Coverage Matrix** — the centrepiece:
A heatmap grid (9 languages × 8 domains). Each cell shows coverage % with colour coding:
- 🟢 Green: 95%+ covered
- 🟡 Yellow: 70–94%
- 🔴 Red: <70% or not started
- ⬜ Grey: roadmap (not active yet)

Click any cell → drill into the gap list for that language + domain.

**Live Stats Bar:**
- Total keys across all domains
- Keys missing (open gaps)
- R.O.S.E.T.T.A. tasks in queue
- Last audit run timestamp

**Gap Feed:**
- Filterable by domain, language, gap type (missing / untagged / quality_suspect)
- Each gap row shows: key, domain, language, snippet, linked `unified_task`
- Inline "dispatch translate" button → creates task immediately

**Translation Velocity Chart:**
- 30-day rolling chart: keys translated per day
- Shows R.O.S.E.T.T.A. output rate so Kytran can see the team working

**R.O.S.E.T.T.A. Work Queue:**
- Active and pending translate tasks pulled from `unified_tasks`
- Shows current batch (keys being translated), language, domain, C.R.E.E.D. status
- Real-time via SSE or 10s poll

**Translation Memory Panel:**
- Browse and edit glossary entries (brand terms, product names, proper nouns)
- E.g. "A.R.C.H.I.E." → never translated, always kept as-is in all languages
- Corrections feed back to R.O.S.E.T.T.A. as context on next run

#### 4. A.R.C.H.I.E. Dialects Section

A dedicated panel framing translation as **A.R.C.H.I.E.'s linguistic identity**:
- Lists all 9 "languages" A.R.C.H.I.E. speaks — 8 human + 1 AI semantic
- Shows dialect notes per language (e.g. "fr = Québécois register", "pt = Brazilian Portuguese")
- `ai` language shown with example semantic descriptions — the machine dialect made visible
- Links to the roadmap (Phase 2–5 language expansions)

This panel is cosmetic-light but gives the tab a soul — it's not just a coverage tracker, it's A.R.C.H.I.E.'s language centre.
